## 3. 时钟系统

### 3.1 PLL 时钟链是怎么跑的（Step 1.1, 2026-08-08）

板子上有个 30MHz 晶振，但 DSP 不是直接用它跑代码的——太慢了。时钟链路是这样的：

```
30MHz 晶振 → PLL 倍频 ×10 = 300MHz → DIVSEL ÷2 = 150MHz (SYSCLKOUT)
                                                    ↓
                              ┌─────────────────────┤
                              ↓                     ↓
                         LSPCLK = 37.5MHz      HSPCLK = 75MHz
                         (÷4, 给 SCI/SPI)     (÷2, 给 ePWM/ADC)
```

- `PLLCR` = 倍频系数（10），`DIVSEL` = 分频系数（2）
- LSPCLK 给"慢"外设用（SCI/SPI/I2C），HSPCLK 给"快"外设用（ePWM/ADC）
- 波特率计算例：SCI 要用 9600bps → BRR = 37.5MHz / (9600×8) − 1 = 487

### 3.2 为什么时钟宏不能写浮点数（Step 1.1, 2026-08-08）

`#define CPU_CLK 150000000L` 是对的。`#define CPU_CLK 150e6` 是错的。

C 语言里 `150e6` 是 double 浮点数，不能做 `>>` 位移和 `&` 位运算。嵌入式代码经常用时钟值算分频系数，必须保持整数。

## 4. GPIO

### 4.1 GPIO 引脚的"切换开关"（Step 1.2, 2026-08-08）

F28335 的每个 GPIO 引脚有 4 个关键寄存器来决定它"现在是什么角色"：

| 寄存器 | 作用 | 例 |
|--------|------|-----|
| GPxMUX | 复用选择：0=GPIO, 1=外设1, 2=外设2, 3=外设3 | GPIO35 MUX=1 → SCI-A TX |
| GPxQSEL | 输入采样方式：0=同步(带滤波), 3=异步(直通) | UART 用 3（异步），PWM 用 0 |
| GPxDIR | 方向：1=输出, 0=输入 | LED 用输出 |
| GPxPUD | 内部上拉：0=启用上拉, 1=禁用 | UART 空闲时保持高电平 |

通信引脚（UART/SPI）选 QSEL=3（异步）是因为信号来自板外，没有和 DSP 时钟同步——用内部时钟采样可能采到亚稳态。

### 4.2 SET/CLEAR 为什么比直接写 DAT 好（Step 1.2, 2026-08-08）

```c
// 好写法：只改 GPIO5，不影响 GPIO0-4 和 GPIO6-31
GpioDataRegs.GPASET.bit.GPIO5 = 1;   // 置高
GpioDataRegs.GPACLEAR.bit.GPIO5 = 1; // 拉低

// 坏写法：会把 GPIOA 端口其他 31 个引脚的值也改了
GpioDataRegs.GPADAT.all |= 0x0020;   // 读-改-写，中断不安全
```

SET/CLEAR 寄存器是硬件原子的：写 1 到某个 bit 就把对应引脚置高/拉低，写 0 的位不变。DAT 寄存器需要读-改-写，如果在读和写之间发生了中断且 ISR 也改了同一个端口，值就坏了。

## 7. 中断与定时器

### 7.1 PIE 中断路由（Step 2.1, 2026-08-08）

F28335 的中断不是"外设直接到 CPU"，而是三级路由：

```
外设 (SCI RX FIFO) → PIE Group (9.1) → CPU INT (INT9) → CPU
```

- 96 个外设中断共享 12 个 CPU 中断线，通过 PIE（Peripheral Interrupt Expansion）分组
- 每个中断要开三把锁：PIEIERx（PIE 级）、IER（CPU 级）、INTM（全局中断 DINT/EINT）
- ISR 末尾必须清 PIEACK，告诉 PIE"Group X 的中断处理完了，可以发下一个了"

### 7.2 中断向量表注册（Step 2.1, 2026-08-08）

```c
EALLOW;                                // 解开寄存器写保护
PieVectTable.SCIRXINTA = &ISRSciRx;    // 把 ISR 函数地址写入向量表
EDIS;                                  // 重新锁上
```

向量表是个函数指针数组，每个中断号对应一个槽位。`PieVectTable` 在受保护的寄存器区，必须先 EALLOW 才能改——这是硬件安全机制，防止程序跑飞时意外改写向量表。

## 8. 串口/通信

### 8.1 SCI (UART) 是怎么收发数据的（Step 2.1-2.2, 2026-08-08）

**发送**：CPU 把字节写入 TX FIFO → SCI 硬件从 FIFO 取出 → 加起始位/停止位 → 按波特率一位一位从 TX 引脚串行送出。

**接收**：RX 引脚上检测到起始位的下降沿 → 按波特率采样 8 次取数据位 → 拼成字节放入 RX FIFO → FIFO 达到触发深度 → 发中断通知 CPU。

**波特率**：每秒发多少 bit。9600 bps = 每 bit 约 104μs，一个字节（1 起始 + 8 数据 + 1 停止 = 10 bit）约 1ms。

### 8.2 FIFO 模式 vs 非 FIFO 模式（Step 2.1, 2026-08-08）

非 FIFO 模式：收一个字节就中断，CPU 必须立刻来取——如果 ISR 被更高级中断抢了超过 1ms，数据就丢了。

FIFO 模式：SCI 内部有 16 级硬件队列。即使 ISR 响应慢了，数据在 FIFO 里排队等着。触发深度设为 1（RXFFIL=1）意味着"有 1 字节就中断"，对 Modbus 透传最合适——不攒数据，实时性好。

### 8.3 SCI 初始化为什么要在 SWRESET=0 下写寄存器（Step 2.1, 2026-08-08）

SCI 模块有个"复位开关"（SWRESET）。初始化的标准做法是：

1. SWRESET=0（模块暂停，配置随便改）
2. 写完所有寄存器（通信格式、波特率、FIFO、中断）
3. SWRESET=1（模块启动，开始收发）

如果在 SWRESET=1 时改配置，模块正在运行中，可能收到一半的数据或发到一半被新配置打断——行为不可预期。

### 8.4 多字节消息回显碎片化问题（Step 2.3 修复, 2026-08-08）⚠️ 踩坑记录

**现象**：从串口工具发送 `01 06 00 00 00 00 00 00`（8 字节），DSP 回显的数据被拆成几段：
```
[收] 01          ← 只有第一字节
[收] 06 00       ← 后面的又分开了
```

**原因**：ISR 每收到 1 字节就立刻置标志 `g_rxReady=1`，主循环看到标志立刻回显，不等后面的字节。这就像快递到了就拆——哪怕整箱货还有 7 件在路上。

**本质**：UART 是按字节异步传输的。PC 虽然一次性发了 8 字节，但在 9600bps 速率下，字节之间有 ~1ms 间隔。DSP 的 ISR 在收到第一字节后几微秒内就触发了，此时后面 7 个字节还在传输线路上没到。

**修复方法**：在主循环中加入帧间静默检测——收到第一字节后不立刻回显，而是等"连续 4ms 没有新字节到达"再一次性回显整个缓冲区。

```
收到标志 → 记录当前字节数 → 等1ms → 字节数变了吗?
  ├─ 变了 → 说明还有数据在路上，重置计时器
  └─ 没变 → 累计静默时间，够4ms就确认帧结束 → 整体回显
```

这实际上是 Modbus RTU 的 3.5 字符间隔帧检测原理（阶段 4 会正式实现）：帧与帧之间至少要有 3.5 个字符时间的静默（@9600bps ≈ 4ms），静默期间收到的连续字节属于同一帧。

**教训**：异步串口通信中，"一次性发"≠"一次性到"。必须靠帧间超时（idle timeout）来判断帧边界，不能假设发送端发完第一个字节后 ISR 能看到全部字节都在 FIFO 里。

## 9. 调试技巧

### 9.1 注释检查工具（Step 1.2+, 2026-08-08）

每次改完代码跑 `python tools/check_comments.py`。如果报"英文注释"，加 `--allow <英文词>` 放行技术缩写（如 `bps`、`FIFO`、`ISR`）。

### 9.2 串口回显是验证通信链路的"最小闭环"（Step 2.3, 2026-08-08）

不写任何应用逻辑，先把"收到啥发回啥"跑通，能证明：
- GPIO 引脚配置正确
- 波特率匹配
- 中断能正常触发
- FIFO 收发通路正常

如果回显都不通，后面的 Modbus 转发一定不可能通。这是硬件调试的黄金法则：先打通物理层，再往上盖协议层。
