# DROOP_SPI_UART_REFACTOR 四步重构实施方案

## 1. 文档目的

本文档用于指导 `DROOP_SPI_UART` 工程从当前可运行版本，逐步重构为职责清晰、实时行为可控、可以持续测试和发布的 F28335 工程。

重构采用四步渐进实施：

1. 冻结功能基线，建立目录和构建骨架。
2. 拆分 Driver/BSP，收敛全部寄存器访问。
3. 建立双循环调度，解决 ISR 与主循环并发问题。
4. 完成算法接口、内存规划、Flash 发布和工程验收。

每一步都必须满足以下基本原则：

- 能独立编译。
- 能通过对应阶段的自动测试。
- 能通过板上 UART→SPI 回归测试。
- 不把目录迁移、功能修改和性能优化混在同一个提交中。
- 当前步骤未验收前，不进入下一步。

## 2. 当前功能基线

在任何重构操作开始前，必须冻结以下当前行为。重构期间除非有明确的缺陷修复任务，否则不得改变这些参数。

| 项目 | 当前值 |
|---|---:|
| 芯片 | TMS320F28335 |
| SYSCLKOUT | 150 MHz |
| HSPCLK | 75 MHz |
| LSPCLK | 37.5 MHz |
| 系统时间基准 | 100 μs/tick |
| SCI-A | 9600 bit/s、8N1 |
| SCI-A 引脚 | GPIO35 TX、GPIO36 RX |
| UART 最大帧长 | 64 个逻辑字节 |
| UART 帧结束间隔 | 40 tick，即 4 ms |
| SPI-A | Master、Mode 0、8位逻辑数据 |
| SPI-A 引脚 | GPIO16 MOSI、GPIO17 MISO、GPIO18 CLK |
| SPI 波特率 | 约 293 kHz |
| SPI 字节间隔 | 10 tick，即 1 ms |
| SPI 单字节超时 | 50 tick，即 5 ms |
| LED | GPIO67、GPIO68，低电平点亮 |

> 注意：C28x 的数据宽度和主机 PC 不完全相同。通信模块继续使用 `uint16_t` 保存一个逻辑 8 位字节，不要在未验证编译器数据模型前批量改成 `uint8_t`。

### 2.1 当前已知架构问题

- `SRC/MAIN.c` 直接操作 PLL、时钟和外设时钟寄存器。
- `firmware/board/board.c` 同时承担 Timer、SCI、SPI、GPIO、ISR 和板级初始化职责。
- SCI ISR 直接调用 `UartFrame_OnByte()`，形成底层模块反向依赖业务模块。
- UART 帧状态由 ISR 和主循环共同修改，存在竞态条件。
- `firmware/comm/led.c` 位于通信目录，却直接访问 GPIO 寄存器。
- SPI 诊断数据以公开可写 `extern` 形式暴露。
- `Led_TriggerRx()`、`Led_TriggerTx()` 当前没有调用者；重构时不得把该现象误认为已经存在的正常闪烁功能。
- DSP 目标仍会扫描 `tests/host`，测试文件仅依靠条件编译生成占位对象。
- Debug 和 Release 都使用 `28335_RAM_lnk.cmd`，尚未形成真正的 Flash 发布配置。

`control/` 和 `algorithm/` 只在实际加入控制功能时创建具体模块，不为追求目录完整而添加没有行为的空实现。

### 3.2 依赖方向

```text
App ───────→ Services ───────→ Drivers ───────→ TI寄存器定义
 │                                  ↑
 ├────────→ Control ─→ Algorithm    │
 │                                  │
 └────────→ BSP ────────────────────┘
```

必须长期保持以下边界：

- `firmware/app`：负责组装、调度、状态机和 ISR 入口。
- `firmware/services`：负责通信协议、桥接状态机、诊断和指示逻辑。
- `firmware/control`：负责系统控制和保护策略。
- `firmware/algorithm`：只做纯计算。
- `firmware/drivers`：直接访问寄存器。
- `firmware/bsp`：保存板级参数和引脚映射，并调用驱动完成初始化。
- `services/control/algorithm` 禁止包含 `DSP2833x_Device.h`。
- `algorithm` 禁止使用寄存器、ISR、`volatile`、系统 tick 和延时函数。

# 第二步：拆分Driver/BSP，收敛寄存器访问

## 5.1 目标

把 `main.c` 和 `board.c` 中的寄存器操作下沉到驱动层，让上层只依赖清晰的硬件接口。

## 5.2 操作步骤

### 5.2.1 拆分系统时钟驱动

从 `main.c` 迁移以下内容到 `drv_sysctrl.c`：

- 看门狗关闭。
- PLL DIVSEL切换与锁定等待。
- HISPCP、LOSPCP设置。
- 外设时钟门控。

建议接口：

```c
typedef struct
{
    uint16_t pll_div;
    uint16_t divsel;
    uint16_t hispcp;
    uint16_t lospcp;
} SysClockConfig;

bool DrvSysCtrl_Init(const SysClockConfig *config);
```

- [ ] PLL等待必须有明确的失败处理策略，不能无限静默等待。
- [ ] 不改变当前时钟值。

### 5.2.2 拆分Timer驱动

从 `board.c` 迁移：

- `ConfigCpuTimer()` 调用。
- Timer启动/停止。
- Timer中断标志清除。
- 100 μs tick维护。

建议接口：

```c
void DrvTimer0_Init(uint32_t period_us);
void DrvTimer0_Start(void);
void DrvTimer0_ClearInterrupt(void);
uint32_t Timebase_Now(void);
```

`uint32_t` 在C28x上不是天然原子操作。主循环读取ISR更新的32位tick时，必须保留稳定读取或短临界区方案。

### 5.2.3 拆分SCI驱动

从 `board.c` 迁移：

- GPIO35/36复用配置。
- SCI波特率和帧格式配置。
- FIFO配置。
- RX状态读取。
- FIFO读取。
- SCI错误恢复。
- SCI中断标志清除。

驱动不得包含 `uart_frame.h`。

### 5.2.4 拆分SPI驱动

从 `board.c` 迁移：

- GPIO16/17/18配置。
- SPI Mode 0和8位配置。
- SPIBRR设置。
- `SPIFFTX.SPIRST`释放。
- 字节启动和完成查询。

建议接口继续兼容当前状态机：

```c
bool DrvSpi_StartByte(uint16_t tx_byte);
bool DrvSpi_TryCompleteByte(uint16_t *rx_byte);
```

必须保留 `SPIFFTX.bit.SPIRST = 1` 对应行为，避免SPI通道被保持在复位状态。

### 5.2.5 拆分GPIO和LED

- [ ] GPIO67/68的引脚配置移动到 `drv_gpio.c` 或 `board.c`。
- [ ] 寄存器写入封装为 `DrvGpio_Write()` 或专用板级LED接口。
- [ ] LED持续时间逻辑移动到 `services/indicator.c`。
- [ ] 本阶段先保持现有“无触发调用”行为，不悄悄增加新功能。

# 第三步：建立双循环和数据所有权

## 6.1 目标

让ISR负责硬实时和最小数据搬运，让主循环负责通信协议和后台任务；消除UART帧状态由ISR与主循环共同写入的问题。

## 6.2 操作步骤

### 6.2.1 增加SCI单生产者单消费者队列

建议新增：

```text
firmware/drivers/sci_rx_queue.c
firmware/drivers/sci_rx_queue.h
```

或将队列作为 `drv_sci.c` 的内部实现，不向上层暴露队列数组。

每个队列元素至少包含：

```c
typedef struct
{
    uint16_t data;
    uint16_t error;
    uint32_t tick;
} SciRxItem;
```

所有权规则：

- SCI ISR是唯一生产者，只修改写索引。
- 主循环是唯一消费者，只修改读索引。
- 队列满时丢弃新数据并增加计数，不覆盖未消费数据。
- 16位索引优先，避免不必要的32位非原子共享操作。
- `volatile` 只用于确实会被并发观察的索引，不把整个业务结构全部声明为 `volatile`。

### 6.2.2 简化SCI ISR

SCI ISR只执行：

1. 快照并检查SCI错误。
2. 有界读取FIFO，最多读取硬件FIFO深度。
3. 将数据写入RX队列。
4. 必要时恢复SCI RX。
5. 清外设中断标志。
6. ACK PIE Group 9。

禁止在SCI ISR中调用：

- `UartFrame_OnByte()`。
- SPI状态机。
- LED持续时间逻辑。
- 格式化输出。
- 阻塞等待。

### 6.2.3 让UART帧模块由主循环独占

将 `uart_frame` 改为上下文接口：

```c
typedef struct
{
    uint16_t buffer[UART_FRAME_CAPACITY];
    uint16_t length;
    uint16_t state;
    uint32_t last_rx_tick;
} UartFrameContext;

void UartFrame_Init(UartFrameContext *context);
void UartFrame_Push(UartFrameContext *context,
                    uint16_t data,
                    uint32_t tick);
bool UartFrame_Service(UartFrameContext *context,
                       uint32_t now);
```

- [ ] UART帧状态只由主循环修改。
- [ ] 去掉帧状态中不再需要的 `volatile`。
- [ ] 补充“ISR发生在帧结束边界”的并发回归测试。

### 6.2.4 建立100 μs时间基准和多速率后台任务

保留100 μs基础tick，并派生1 ms、10 ms和100 ms任务。

任务划分：

| 执行域 | 内容 |
|---|---|
| Timer ISR | tick递增、释放周期事件、清标志 |
| SCI ISR | FIFO到环形队列、错误快照 |
| 主循环每轮 | 消费SCI队列、UART组帧、SPI状态机 |
| 1 ms任务 | 通用服务和短周期后台任务 |
| 10 ms任务 | 状态机、慢速保护、将来的下垂/慢速外环 |
| 100 ms任务 | LED、诊断快照、低速通信和维护任务 |

主循环参考结构：

```c
for (;;)
{
    uint32_t now = Timebase_Now();

    App_ProcessSciRx(now);
    SpiBridge_Service(now);

    if (Scheduler_Take1ms())
    {
        App_Task1ms(now);
    }

    if (Scheduler_Take10ms())
    {
        App_Task10ms(now);
    }

    if (Scheduler_Take100ms())
    {
        App_Task100ms(now);
    }
}
```

SPI状态机必须保持每轮调用，不能只在1 ms任务里调用。

### 6.2.5 将SPI请求升级为桥接服务

重命名建议：

```text
spi_request.c/.h → spi_bridge.c/.h
```

桥接服务内部负责：

1. 检查UART完整帧。
2. 获取该帧所有权。
3. 启动SPI逐字节状态机。
4. 处理完成和超时。
5. 释放UART帧。
6. 产生RX/TX指示事件。

`main.c` 不再直接拼接多个模块状态判断。

### 6.2.6 收口全局数据

- [ ] 每个模块使用自己的上下文结构体。
- [ ] 配置数据声明为 `const`。
- [ ] 删除公开可写诊断 `extern`。
- [ ] 诊断信息通过快照接口读取。
- [ ] 每个共享字段标明唯一写入者。

不要建立包含所有模块字段的巨型 `g_sSystemParam`。

### 6.2.7 时间计算统一采用回绕安全方式

周期差值使用无符号减法：

```c
elapsed = now - start;
```

绝对截止时间判断使用：

```c
if ((int32_t)(now - deadline) >= 0)
{
    /* deadline reached */
}
```

所有定时模块都必须覆盖 `0xFFFFFFFF → 0x00000000` 回绕测试。

## 9. 回退规则

### 9.1 触发条件

出现以下任一情况时，启动回退流程：

- 板上 UART→SPI 功能回归失败（与基线行为不一致）。
- 新增功能引入的寄存器值变化无法在 30 分钟内解释。
- Host 测试通过但硬件行为异常（说明 Host mock 与真实外设存在差距）。
- 连续两轮修复后同一验收项仍然失败。

### 9.2 回退前证据保存

发现硬件行为变化后，首先停止进入下一阶段，然后在指定目录保存证据：

```text
tests/hardware/failures/YYYYMMDD_<issue>/
```

必须保存的内容：

1. **构建日志** — CCS Debug/Release 完整构建输出。
2. **二进制与映射** — `.out` 和 `.map` 文件。
3. **寄存器快照** — 通过 JTAG `readMemory` 读取的关键外设寄存器值（SCICCR、SPICCR、SPIBRR、SPIFFTX、PLLSTS 等）。
4. **诊断计数器** — 重构前后 `g_app.diag` 的快照对比值。
5. **串口原始字节** — Serial Console 中实际收发的原始字节序列。
6. **逻辑分析仪/示波器波形**（如有）。
7. **复现步骤** — 最小化复现流程，精确到输入字节序列和间隔时间。
8. **CCS 配置和编译器版本** — `cl2000 --version` 输出、`.cproject` 编译器版本。

### 9.3 定位归属

对比最近一个"已通过验收门"的真实 Git 提交或标签（如 `droop-spi-uart-refactor-software-baseline`），按以下分类逐项判断：

| 变更类别 | 检查方法 |
|----------|----------|
| 文件迁移 | `diff -r` 对比目录结构，确认源文件移动后包含路径是否正确 |
| 寄存器初始化 | `diff` `.map` 中 `.cinit` 段；JTAG `readMemory` 对比关键外设寄存器 |
| ISR 顺序 | 检查 PIE 优先级、IER 使能顺序、PIEACK 清除时机 |
| 队列所有权 | 确认 SCI ISR 是否只写队列、主循环是否只读队列 |

| 时间参数 | 检查 UART 帧间隔、SPI 字节间隔、SPI 超时等 tick 换算是否正确 |
